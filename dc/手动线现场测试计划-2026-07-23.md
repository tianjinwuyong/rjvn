# 瑞晶越南工厂手动线现场测试计划

## 1. 基本信息

- 测试日期：2026-07-23
- 测试范围：手动线工站 Agent、MES、3D Line、扫码枪、设备数据源及维修闭环
- MES 地址：`192.168.6.155`
- 3D Line：`http://192.168.6.155:5178/#manual-line-3d`
- 测试目标：验证现场数据及时、准确、完整地从工站同步到 MES，并由 3D Line 统一监控
- 数据主链：`工站 Agent → MES → 3D Line`

## 2. 核心原则

1. 工站设备数据是现场事实来源。
2. MES负责统一保存、校验、合并、追踪和发布。
3. 3D Line只负责显示、监控和报警，不修改生产事实，不锁定工站。
4. 扫码枪只做识别、NG检查、重码检查、顺序检查及交接确认，不直接写入正式SN表。
5. 正式SN只能来自设备CSV、Excel或生产数据库；入库前必须执行重码校验。
6. 所有测试数据必须标记为`TEST`，测试结束后清除，不得污染生产统计。

- [ ] 确认所有工站IP、工站编码、MES地址和端口正确。
- [ ] 确认每台工站只运行一个Agent实例。
- [ ] 确认所有工站时间同步，时区一致。
- [ ] 确认扫码枪连接正常并能输入完整SN。
- [ ] 确认ICT CSV、FCT Excel、SQL Server、MySQL等真实数据源可访问。
- [ ] 备份现场Agent、配置文件和本地SQLite。

- [ ] 准备允许使用的测试SN，并确认带`TEST`标识。
- [ ] 打开至少两个浏览器，同时显示3D Line，用于一致性检查。
- [ ] 记录测试开始前各箱子、维修工单和SN数量基线。

## 5. 验收标准

### 5.1 及时性

- 现场测试结果产生后，MES应在5秒内收到。
- MES收到数据后，3D Line应在3秒内更新。
- 工站心跳周期为5秒；连续10秒无心跳应显示离线或异常。

### 5.2 准确性

- SN、母板号、槽位、PASS/NG、错误代码与原始文件完全一致。
- MES、工站本地和所有3D浏览器显示一致。
- 同一文件未变化时不得重复读取、重复入库或重复刷新。

### 5.3 完整性

- 每个事件必须包含唯一事件编号、SN、工站、时间、动作和结果。
- NG必须保留首次发现时间、来源工站、故障类型、维修和复活全过程。
- 工单必须保留投入、产出、NG、维修、报废和数量差异记录。

## 6. 测试用例

### T01 工站在线与心跳

1. 依次启动所有手动线Agent。
2. 在MES和3D Line检查对应工站状态。
3. 关闭一个Agent并等待10秒，再重新启动。

通过标准：

- [ ] 心跳每5秒更新。
- [ ] 关闭后正确显示离线。
- [ ] 重启后自动恢复在线，无重复工站实例。

### T02 数据源显示与连接

1. 检查每个工站UI的数据源路径或数据库连接信息。
2. 打开原始内容表格，核对最新记录。
3. 临时断开数据源，再恢复。

通过标准：

- [ ] 数据源名称、路径、表名正确。
- [ ] 原始数据可查看，且与设备一致。
- [ ] 断开与恢复状态能同步到MES和3D。

### T03 扫码枪基础检查

1. 扫描有效SN。
2. 扫描无效格式。
3. 扫描确认NG SN。
4. 扫描历史重码SN。
5. 连续快速扫描多个SN。

通过标准：

- [ ] 扫码结果立即显示。
- [ ] 无效格式不入库、不播报正式产品信息。
- [ ] 确认NG全线拦截。
- [ ] 重码触发声光报警并可快速解除。
- [ ] 扫码记录不进入正式SN表。

### T04 ICT真实数据解析

1. 让ICT设备生成一盘真实CSV。
2. 核对12个SN、槽位、结果和错误代码。
3. 保持文件不变，观察30秒。
4. 生成下一盘CSV。

通过标准：

- [ ] 12个槽位与CSV完全一致。
- [ ] NG槽位保持红色，直到新CSV到达。
- [ ] 相同CSV不重复读取、不闪烁、不重复入库。
- [ ] 新CSV触发一次更新。

### T05 FCT真实数据解析

1. 使用`D:\ATS\测试报表\`中的当日真实Excel。
2. 完成一盘FCT测试。
3. 核对12个SN、槽位、结果和错误代码。
4. 保持Excel不变，观察30秒。
5. 在同一Excel中追加下一组记录。

通过标准：

- [ ] 只读取生产目录，不读取副本或统计目录。
- [ ] 只显示最新测试组，历史组不得覆盖当前画面。
- [ ] 文件无变化时不重复解析和刷新。
- [ ] 最新一组数据与Excel完全一致。

### T06 ICT/FCT复检

1. 制造一盘NG。
2. 按下复检按钮。
3. 扫描该母板任意子板SN。
4. 分别执行复检PASS和复检FAIL场景。
5. 不按复检按钮再次扫描同一SN。

通过标准：

- [ ] 复检按钮只旁路下一次扫码或下一组文件。
- [ ] 复检期间不触发重码报警。
- [ ] 一次复检结束后自动恢复正常检测。
- [ ] 复检PASS后进入复活流程。
- [ ] 复检FAIL后保持NG并保留历史。

### T07 MES合并ICT与FCT母板

1. 使用同一母板完成ICT和FCT测试。
2. 分别在不同槽位制造ICT NG和FCT NG。
3. 同一槽位同时制造ICT和FCT NG。

通过标准：

- [ ] MES通过母板身份及成员SN正确匹配。
- [ ] 合并结果显示ICT NG、FCT NG、ICT+FCT NG。
- [ ] 不同母板不得错误合并。

### T08 分板工位识别

1. 扫描母板任意一个子板SN。
2. 检查整盘12槽位布局。
3. 分别取出ICT NG、FCT NG、ICT+FCT NG。

通过标准：

- [ ] 扫描后自动确认，无额外扫码确认按钮。
- [ ] 能通过任意子板SN识别整盘。
- [ ] 三类NG箱和PASS箱内容正确。
- [ ] 分板本地、MES和3D箱子完全一致。

### T09 NG送维修

1. 在分板工位选择当前NG批次。
2. 由操作员或品质人员确认送往维修站。
3. 检查MES维修工单。
4. 检查3D NG流向动画和倒计时。

通过标准：

- [ ] 人工确认后才允许送出。
- [ ] MES生成唯一维修工单。
- [ ] 工单包含SN、母板、槽位、NG类型、来源工站和发现时间。
- [ ] 送出后对应NG箱清空，但MES历史不得删除。

### T10 维修接收与维修记录

1. 维修站扫描NG SN接收维修工单。
2. 填写故障原因、维修方式、人员和更换物料。
3. 完成维修。

通过标准：

- [ ] 维修站扫码后才算接收。
- [ ] 工单状态由待接收变为维修中。
- [ ] 更换物料编码、批次和数量完整保存。
- [ ] MES和3D实时更新维修状态。

### T11 NG复活与返回

1. 维修完成后申请复活。
2. 品质和线长分别批准。
3. MES生成返回交接单。
4. 原来源工站扫描SN接收。

通过标准：

- [ ] 未获得双重批准不得复活。
- [ ] 必须返回指定来源工站。
- [ ] 原工站扫码接收后才解除确认NG。
- [ ] MES广播复活状态，各工站本地NG缓存更新。
- [ ] 完整审计记录不可删除。

### T12 超时报警

分别验证：

- [ ] NG在发现工站停留超过20分钟。
- [ ] 送出后15分钟未被维修站接收。
- [ ] 维修总时间超过2小时。
- [ ] 修复后15分钟未被原工位接收。
- [ ] 产品在普通工位滞留超过配置时间。

通过标准：声光报警、MES记录和3D显示同时出现；手动解除只关闭报警，不删除事件。

### T13 工序顺序与跳站拦截

1. 正常按顺序流转一个SN。
2. 尝试跳过ICT、FCT、分板或其他任意工站。
3. 使用维修返回SN继续生产。

通过标准：

- [ ] 正常顺序允许通过。
- [ ] 跳站被MES和工站拦截。
- [ ] 3D只显示和报警，不执行锁定。
- [ ] 维修返回后从指定工位恢复顺序。

### T14 工单与数量平衡

1. 建立测试生产工单。
2. 执行投入、PASS、NG、维修、报废和包装。
3. 比较前站出站与后站入站数量。

通过标准：

- [ ] 3D正确显示当前生产工单和维修工单。
- [ ] 投入、PASS、NG、维修、报废数量可以对账。
- [ ] 数量短缺必须填写原因并产生MES记录。
- [ ] 前站出站与后站入站不一致时报警。

### T15 绑码、装箱与栈板

1. 完成板码与外壳码绑定。
2. 完成产品SN与箱码绑定。
3. 完成箱码与栈板码绑定。

通过标准：

- [ ] 映射关系在工站本地和MES都有记录。
- [ ] 3D能显示箱内产品和栈板内容。
- [ ] 所有二维码均绑定正确工单。
- [ ] 重复绑定、跨工单绑定和NG绑定被拦截。

### T16 多浏览器一致性

1. 同时打开两个3D Line浏览器。
2. 产生心跳、PASS、NG、报警和维修状态变化。
3. 刷新其中一个浏览器。

通过标准：

- [ ] 两个浏览器显示内容一致。
- [ ] 新页面先加载MES快照，再接收实时事件。
- [ ] 刷新后数据不消失、不回退。

### T17 断网与恢复

1. 断开一个工站网络。
2. 在断网期间产生测试事件。
3. 保持断网20分钟。
4. 恢复网络。

通过标准：

- [ ] 断网事件保存在本地待同步队列。
- [ ] 恢复后按原始顺序补传。
- [ ] MES不重复生成SN、NG或维修工单。
- [ ] 3D恢复后重新加载快照并继续实时更新。

### T18 积压与压力恢复

分别积压100、500、1000条测试事件后恢复连接。

通过标准：

- [ ] 数据无丢失、无重复、顺序可追踪。
- [ ] MES和数据库无明显阻塞。
- [ ] 3D仍可操作，不出现页面崩溃或持续闪烁。
- [ ] 同步积压数量最终归零。

## 7. 端到端核心验收流程

必须完整跑通以下主线：

`ICT真实测试 → FCT真实测试 → MES合并母板 → 分板扫码识别 → NG分类 → 人工确认送维修 → MES生成维修工单 → 维修扫码接收 → 维修记录 → 品质与线长批准 → 返回原工位 → 原工位扫码接收 → NG复活 → 后续工位放行 → 包装 → 外箱绑定 → 栈板绑定`

只有整条流程通过，手动线核心闭环才判定通过。

## 9. 缺陷记录要求

每个失败项必须记录：

- 缺陷编号和发现时间
- 工站编码、工站IP和Agent版本
- 使用的SN、母板号、工单号和维修工单号
- 原始CSV、Excel或数据库记录位置
- 工站UI、MES和3D截图
- MES事件编号和本地事件编号
- 预期结果、实际结果和复现步骤
- 是否影响继续生产
- 临时处置、责任人和修复期限

## 10. 停止测试条件

出现以下任一情况应立即停止相关工站测试：

- 生产数据被模拟数据污染。
- 正式SN重复写入或确认NG被错误放行。
- 工站数据与MES发生无法解释的覆盖。
- 维修复活未经批准生效。
- 工序跳站未被拦截。
- 数据源解析造成大量错误记录。
- MES、数据库或3D持续不可用。
